# Firstpractice
# Эмулятор оболочки UNIX

Графический эмулятор командной строки UNIX-подобной ОС на Python (tkinter).
Работает с виртуальной файловой системой (VFS), которая загружается из JSON-файла и целиком хранится в памяти.

## Возможности

- GUI-приложение: окно вывода и строка ввода внизу.
- Заголовок окна формируется из реальных данных ОС (`hostname - username`).
- Параметры командной строки: путь к VFS и путь к стартовому скрипту.
- Выполнение стартового скрипта с отображением ввода и вывода, как в диалоге.
- VFS из JSON-файла, все операции выполняются только в памяти.
- Команды: `ls`, `cd`, `tree`, `who`, `touch`, `chmod`, `exit`.
- Обработка ошибок: неверные пути, неизвестные команды и флаги, неверные аргументы.


## Запуск

```
python File.py [--vfs ПУТЬ_К_JSON] [--script ПУТЬ_К_СКРИПТУ]
```

| Параметр | Описание |
|---|---|
| `--vfs` | JSON-файл с описанием виртуальной файловой системы |
| `--script` | Стартовый скрипт с командами эмулятора |

При запуске в окно выводятся все заданные параметры (отладочный вывод).

Примеры:

```
python File.py
python File.py --vfs vfs/deep.json
python File.py --vfs vfs/deep.json --script scripts/stage4.txt
```

Без `--vfs` файловой системы нет: команды `ls`, `cd`, `tree`, `touch`, `chmod` сообщат «VFS не загружена».

## Формат VFS

VFS это JSON-объект. Значение-объект `{...}` это папка, значение-строка это файл с таким содержимым. Бинарные данные хранятся строкой с префиксом `base64:`.

```json
{
  "home": {
    "user": {
      "docs": { "report.txt": "report" },
      "todo.txt": "todo"
    }
  },
  "logo.bin": "base64:AAECAw=="
}
```

Корень `/` эмулятора это корень JSON. Выйти за пределы VFS нельзя.

Примеры в папке `vfs/`:

| Файл | Назначение |
|---|---|
| `minimal.json` | минимальная VFS (пустой корень) |
| `several.json` | несколько файлов, один бинарный |
| `deep.json` | четыре уровня вложенности |
| `broken.json` | намеренно сломанный JSON (проверка ошибки) |
| `wrong_root.json` | корень не папка (проверка ошибки) |

JSON на диске эмулятор не изменяет. Изменения, сделанные командами, живут только в памяти и пропадают при закрытии.

## Команды

| Команда | Описание |
|---|---|
| `ls [-l] [путь]` | содержимое папки; `-l` показывает тип, права, размер и время изменения |
| `cd [путь]` | сменить текущую папку; без аргумента переход в корень; поддерживаются `.`, `..`, абсолютные и относительные пути |
| `tree [путь]` | показать дерево каталогов, по умолчанию от текущей папки |
| `who` | показать имя пользователя, терминал и время запуска эмулятора |
| `touch [-c] файл...` | создать пустой файл или обновить время существующего; `-c` не создаёт отсутствующий файл |
| `chmod РЕЖИМ путь...` | изменить права, режим из трёх восьмеричных цифр (например `644`, `755`) |
| `exit` | завершить работу |

Строка ввода разбирается по пробелам: первое слово это команда, остальные это аргументы. Приглашение показывает текущую папку.

### Права доступа

Права хранятся отдельно от VFS и показываются в `ls -l`. Новые файлы получают `rw-r--r--`, папки `rwxr-xr-x`. Права только хранятся и отображаются, доступ по ним не ограничивается.

## Стартовые скрипты

Стартовый скрипт это текстовый файл с командами эмулятора. Команды выполняются последовательно, пустые строки и строки с `#` пропускаются. Для каждой команды в окне видны ввод и вывод. Ошибочная строка пропускается с сообщением `[ОШИБКА]: строка N, команда пропущена`, выполнение продолжается. Команда `exit` останавливает скрипт.

| Скрипт | Что проверяет | VFS |
|---|---|---|
| `scripts/ok.txt` | корректный скрипт | любая |
| `scripts/with_errors.txt` | ошибочные строки внутри скрипта | любая |
| `scripts/with_exit.txt` | остановка скрипта по `exit` | любая |
| `scripts/stage4.txt` | `ls`, `cd`, `tree`, `who` во всех режимах и ошибки | `vfs/deep.json` |
| `scripts/stage5.txt` | `touch`, `chmod` во всех режимах и ошибки | `vfs/deep.json` |

## Скрипты ОС для тестирования

Файлы `.bat` в папке `tests/` запускают эмулятор с разными параметрами. Запускать из корня проекта (в PowerShell: `.\tests\имя.bat`). Каждое окно эмулятора нужно закрыть, чтобы запустился следующий вызов.

| Файл | Что проверяет |
|---|---|
| `test_ok.bat` | параметры `--vfs` и `--script` по отдельности и вместе, корректные данные |
| `test_errors_in_script.bat` | скрипты с ошибками и с `exit` |
| `test_bad_paths.bat` | несуществующие пути к VFS и скрипту |
| `test_vfs_good.bat` | минимальная, многофайловая и глубокая VFS |
| `test_vfs_bad.bat` | отсутствующий, сломанный и неверный по корню JSON |
| `test_stage4.bat` | полный скрипт этапа 4 |
| `test_stage5.bat` | полный скрипт этапа 5 |

## Устройство кода

| Функция | Назначение |
|---|---|
| `parse_args` | разбор параметров командной строки |
| `println` | вывод строки в окно |
| `debug_params` | отладочный вывод параметров запуска |
| `load_vfs` | загрузка JSON в память, проверка корректности |
| `count_nodes` | рекурсивный подсчёт файлов и папок |
| `resolve` | превращает строку-путь в список имён от корня с учётом текущей папки |
| `get_node` | находит узел VFS по списку имён |
| `command` | разбор строки и вызов нужной команды; возвращает `ok`, `error` или `exit` |
| `run_script` | выполнение стартового скрипта |
| `cmd_ls`, `cmd_cd`, `cmd_tree`, `cmd_who`, `cmd_touch`, `cmd_chmod` | реализации команд |

Текущая папка хранится списком имён (`cwd`), права и время изменения в словарях `modes` и `mtimes`, ключом служит полный путь.

## Этапы разработки

1. **REPL**: GUI, заголовок из данных ОС, парсер, заглушки `ls`, `cd`, `exit`.
2. **Конфигурация**: параметры `--vfs` и `--script`, отладочный вывод, стартовый скрипт, скрипты ОС.
3. **VFS**: загрузка из JSON в память, примеры VFS, скрипты для разных вариантов VFS.
4. **Основные команды**: `ls`, `cd` по VFS, `tree`, `who`, стартовый скрипт.
5. **Дополнительные команды**: `touch`, `chmod` (только в памяти), стартовый скрипт.
